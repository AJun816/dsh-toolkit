# 技能编写（Skill Author）

把「领域最佳实践」写成模型可自动激活、可按需加载、可溯源保鲜的 SKILL.md。方法论来自本机三个优秀样本的逆向工程 + Anthropic Agent Skills 官方标准。

> 基线失败：技能写成一篇无路由的百科长文——模型不知道何时该用它；或写成无契约的口号集——加载了也产出不了可核对的交付物；或数字无溯源——半年后悄悄变成错误共识的放大器。
> 不启用：一次性任务的临时指引（直接写进任务描述即可）；插件代码本身的工程结构（那是代码问题不是技能问题）。

## 何时介入

编写或评审 SKILL.md、设计技能目录结构、给现有技能做保鲜复验。

## 体量经济学（三层结构）

| 层 | 体量基准 | 职责 | 样本证据（2026-11-01 量测） |
|---|---|---|---|
| 路由层 SKILL.md | ≤200 行（契约样本仅 47 行） | 触发条件、速查表、流程骨架——模型每次加载的全量 | ux-audit 全文 47 行；copilotkit-agui 91 行 |
| 深度层 references/ | 按需，不设上限 | 完整规范/逐步示例/流程图/API 参考；正文点名「何时读哪份」 | copilotkit-agui：路由 91 行 vs references 2156 行（≈1:24） |
| 数据层 data/ + scripts/ | 数据驱动型才要 | CSV/JSON 知识库＋标准库检索脚本＋数据契约测试＋溯源元数据 | ui-ux-pro-max：3.7MB 数据、stdlib-only BM25、17 个测试文件 |

判断口诀：内容是「决策规则」进路由层；是「查阅材料」进深度层；是「可检索事实」进数据层。

## 目录级契约（决定模型能否自动激活）

一、name：kebab-case，全目录唯一（/^[a-z0-9]+(?:-[a-z0-9]+)*$/）。
二、description：一句话写清「做什么＋何时用」，含 3-5 个触发词与典型用户措辞，跨语言环境加英文关键词。description 是模型的路由依据——写得像广告词就永远不会被激活。
三、双层可见性：modelInvocable（模型自动激活）与 userInvocable（用户显式调用）默认都开。

## 正文七件套（缺一即评审不过）

一、基线失败：开门第一句写「本技能要防的、观察到的失败模式」——反面锚点比十条正面规则更防跑偏。
二、何时介入／不启用：正向触发＋负向路由（重叠场景点名应改用哪个兄弟技能，别让模型掷硬币）。
三、流程：编号步骤；顺序不可跳的写明「顺序不可跳」。
四、量化指标：数字不是形容词（「首屏 JS ≤200KB gzip」而不是「性能要好」）。
五、常见错误：3-6 条实践中真会犯的错，每条带改法。
六、安全护栏：涉及写操作/生产环境/资金的技能必须有显式红线。
七、交付物：按序列产出物（路径/格式/验收方式）——交付契约化，验收才有分母。

## 查询契约（数据驱动技能的检索纪律）

一、最小模式：单一 domain/stack 能答的不用聚合模式。
二、单一主导意图：每次查询 2-5 个有效词＋一个约束（产品/平台/交互），不塞整张检查单。
三、结果验证：核对返回的 domain/类目/首条身份是否贴合产品语境；偏题重试一次（收窄或显式 domain）；仍空则明说「无匹配，以下为通用兜底」，禁止把 0 结果包装成数据。
四、输出为消费优化：长字段截断控 token，机器可读留 JSON 通道。

## 溯源与保鲜

一、事实性数字必须有「业界基准（核验日期）」＋「来源」两节，URL 直指官方原文。
二、来源节标保鲜 SLA（默认 90 天）：超期数字不得写进新交付物，先按链接重验。
三、references 从代码库/文档生成时配 sources.md 逐文件列明出处——可复查、可再生成。
四、数据层配 provenance 元数据：每条记录 verifiedAt/status/sla/confidence。

## 常见错误

一、SKILL.md 写成 500+ 行百科——路由层越肥激活越迟钝，深度外移 references。
二、description 只写「擅长 X」不写何时用——模型无法路由，技能等于死代码。
三、只有正面规则，没有基线失败与常见错误——同一个坑每个新会话重踩一遍。
四、兄弟技能边界不清——用「不启用」行互相点名交接。
五、数字无核验日期——上游发版后技能变成过期共识。
六、把安全提醒当废话删掉——写操作类技能没有护栏是事故流水线。

## 业界基准（2026-11-01 本机逆向 + 联网核验）

一、官方标准（Anthropic Agent Skills，开放标准）：SKILL.md 以 name＋description 元数据声明触发；渐进披露是核心设计——元数据常驻、正文按需、引用文件再按需。
二、本机样本实测：ux-audit 47 行纯契约（七部分交付契约＋量化表＋常见错误＋安全护栏）；copilotkit-agui 路由 91 行/深度 2156 行/sources.md 逐文件溯源；ui-ux-pro-max 数据层 3.7MB（BM25 stdlib 检索、17 测试文件、data-provenance 保鲜政策 365 天重验/90 天待复审）。
三、三样本共同点：都显式回答「何时不用我」；都把失败模式当第一等公民；都零外部依赖（标准库即可运行）。
