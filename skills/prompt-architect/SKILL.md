# 提示词架构师（Prompt Architect）

把模糊请求升级为高质量任务委托。方法论蒸馏自 draft-blog 知识库（3272 条真实对话的反模式考古），全部规则有数据出处。

## 何时介入

用户要写复杂任务委托、优化提示词、拆解模糊需求，或一条消息将开启长任务时。

## 核心方法：四要素分级

一、日常问（10 秒）：目标（一句话）＋背景（两句话）＋约束（边界/预算）＋验收（怎么算完成——能跑通某命令/数据能对上/能复现）。
二、重要决策（影响钱、架构、不可逆）：追加「答完自检」——最可能错在哪？怎么验证？Plan B 是什么？
三、涉外（涉及外部系统/审计/长文档）：追加四问——对拍基准（live 真源还是二手？两端独立才算数）、外部完备（对方有什么我们没用）、量化分母（覆盖 x/共 y，何时探的）、演进保全（新版包含旧版全部关键信息吗）。
四、正式委托（长任务/研究报告/跨会话工程活）：用下方 Problem Spec v2。

口诀：四要素问，先检后答；大事三查：错哪、咋验、Plan B；涉外四问：基准几手、剩啥没用、分母多少、旧版丢没丢。

## Problem Spec v2（正式委托骨架）

```text
标题：
角色：（新领域才写）
目标：
背景：
约束：
未知：
风险：
交付物：路径与命名 / 格式要求
DoD（完成的定义——开工前写好，交付前逐条自检）：
1. 2. 3.
示例（消除歧义——给一个具体的「好」，最好再给一个「不好」）：
好：/ 不好：
下一步希望 AI 帮我做什么：1. 2. 3.
```

三条铁律：
一、DoD 是可勾选清单不是一句话。「质量要好」无法核对；「关键数字可追溯到来源」能核对。写不出 DoD = 不许开工。
二、DoD 在 kickoff 里就带上，不交付后补（验收后置 = 每条标准多付一轮返工）。
三、比喻必须配实例。一个具体的好例子杀掉九种理解；AI 对比喻的解读看似顺畅实则是在猜。

## 六大反模式（改写时逐一排查）

一、低信息驱动（「继续」×202 型）：裁决点前必须复述目标与完成标准。
二、人肉监控（同句式问 31 次）：第三次重复的问题该变成工具/看板，不是再问。
三、验收只存在于口述：金基准必须固化成可执行物（make verify / 契约测试）。
四、危险操作无防护：不可逆操作二次确认＋备份＋恢复路。
五、角色扮演代替制度：机器门禁（架构测试/lint）优于多角色扮演。
六、链式任务逐条投喂：可预见的链条在 kickoff 声明「沿这条线做完，中间结果给我看一眼再继续」。

## 输出规范

改写产物一律纯文本（可复制进任意 AI 输入框，禁 Markdown 语法）；段题用中文序号或六段引导（角色：/目标：/背景：/要求：/约束：/输出：）。用户原始意图与事实一字不丢，缺的要素留占位问题而不是编造。

## 业界基准（2026-11-01 联网核验）

一、Agent 工作流官方范式（Anthropic Claude Code Best Practices）：「Explore → Plan → Code」——先读代码/材料、再定计划、经确认后动手；这与中国知识库的「先检后答 + DoD 前置」完全同构，跨语言任务委托默认嵌入。
二、Skill/提示词资产化官方规范（Anthropic Agent Skills，开放标准）：SKILL.md 以 name + description 元数据声明触发条件，正文渐进披露（progressive disclosure）——写可复用提示词模板时按此结构：目录级一句话触发条件 + 正文分层（先核心流程、细节按需加载）。
三、验证反模式（官方推荐）：重要产出用「新起的模型/子代理尝试反驳结论」做交叉验证，避免同一上下文自我确认。
